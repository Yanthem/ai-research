# DCI 검색 절차

DCI(Direct Corpus Interaction, arXiv 2605.05242)는 검색기 대신 에이전트가 터미널 도구로 원문 폴더를 직접 뒤지는 방식이다.
Claude Code의 Grep(ripgrep)·Glob·Read가 곧 논문의 도구 세트다. 논문의 DCI-Agent-CC도 Claude Code였다.

## 대상 폴더
- 기본: `data/corpus/` (만드는 법은 `agentic-search/README.md`). 사용자가 다른 폴더를 말하면 그 폴더.
- 그 폴더 밖의 파일로 답하지 않는다. 기억으로 답하지 말고 파일에서 확인한다.

## 절차
1. **질문 쪼개기**: 질문에서 고유명사, 파일 이름, 명령어, 숫자 같은 "정확히 일치할 문자열"을 뽑는다. 한국어 단어는 조사를 뗀 어간으로 쓴다(`스킬을` 말고 `스킬`).
2. **동의어와 다른 언어 표기를 같이 찾는다**: 한 번에 여러 Grep을 병렬로 던진다. 예: `maker|메이커`, `checker|체커|검증자`, `plan mode|계획 모드|Shift\+Tab`.
   영어 키워드만 쓰면 한국어 번역본에서 놓친다(실측: maker/checker 로는 강의 13을 못 찾음).
3. **넓게 → 좁게**: 먼저 `files_with_matches`나 `count`로 어떤 파일에 몰려 있는지 본다. 그다음 상위 파일만 `-n -C 3`로 주변 줄을 본다.
   결과가 수백 줄이면 키워드를 하나 더 겹친다(파일 목록에 두 번째 Grep을 거는 식).
4. **필요한 부분만 읽는다**: Read는 offset/limit으로 해당 구간만 연다. 큰 파일 전체를 읽지 않는다.
5. **전제를 확인한다**: 질문의 전제가 원문과 다르면 그렇다고 말한다(실측 예: "SKILL.md에 반드시 필요한 필드"를 물었지만 원문은 name 선택, description 권장).
6. **멈출 때**: 근거 줄을 2곳 이상 찾았거나, 키워드 조합을 5번 바꿔도 안 나오면 멈추고 "못 찾음"이라고 답한다.

## 답 형식
- **답**: 한두 문장
- **근거**: `경로:줄번호` 인용 1~3개와 그 줄의 짧은 발췌
- **확신도**: 0~100. 70 이하이면 무엇을 더 찾아봐야 하는지 한 줄

## 코퍼스가 클 때 (DR-DCI)
문서가 수만 개를 넘거나 Grep 한 번에 수천 줄이 나오면, 먼저
`python agentic-search/pull.py "<질문 요지>" --k 20` 으로 관련 문서를 `data/workspace/`로 끌어온 뒤
그 폴더 안에서만 위 절차를 반복한다. 부족하면 다른 질의로 다시 pull 한다(workspace가 넓어진다).
